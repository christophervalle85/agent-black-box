# Agent Black Box v0.8 — Synthetic native-transfer security acceptance

**Scope:** A Mac-only, opt-in, fixed 39-byte synthetic import security prototype. This is not a real-file transfer feature or a production authorization claim. Real import/export remains disabled.

## Release-candidate checks

Run these **on the local Mac** from `feature/v0.8-native-transfers`, after pulling the latest commit:

```sh
npm test
MCP_SANDBOX=off npm run mcp:mac-xpc-native-reviewed -- handoff-rsa-keychain-suite
```

The suite uses the **existing** provisioned software Keychain RSA identity and its separately enrolled fingerprint. **Do not provision or rotate the identity.** It performs three independent synthetic reviews with two Touch ID approvals each: signed helper consent and signed host consent.

Required evidence:

- Enrolled RSA public fingerprint matches the existing local trust pin before native host signing.
- The native signer independently rechecks the HMAC audit chain, anchored checkpoint, and exact final reservation **before and after** operator consent.
- The signer refuses a duplicate review from a separate process using the exact spent-nonce result and returns no signature.
- Genuine signed-field mutations are rejected before native host Touch ID/XPC.
- The sandboxed worker rejects durable replay across a verified process exit and fresh worker instance.
- Crash-before-reservation returns `NO_MARKER` but never authorizes a retry or claims success.
- Crash-after-reservation-before-ACK returns `MATCHING_MARKER` but never claims a real transfer succeeded.
- Both crash outcomes remain `UNCERTAIN` in the reopened HMAC audit and approvals remain nonretryable.
- The suite prints `PASS: One pinned Keychain controller identity passed native consent, signed XPC durable replay/restart and both uncertain-crash gates across three separate synthetic reviews.`

The separate signer cancellation test also passed on an actual Mac in October 2026. To recheck it deliberately, run:

```sh
MCP_SANDBOX=off npm run mcp:mac-xpc-native-reviewed -- handoff-rsa-keychain-deny
```

**Choose Cancel at the controller signer prompt.** Expected: no native receipt host launched, no signature, audit still uncertain and nonretryable.

## Evidence and limits

Earlier integrated Keychain/restart/crash and signer nonce tests passed on a real Mac (user-provided terminal transcripts, October 2026). The new native read-only HMAC verifier passed Apple's CI-compiled positive and malformed-checkpoint/audit-directory vectors before automatic feature CI was disabled. **The combined, updated suite requires another real-Mac acceptance run**. Do not mark this release candidate accepted or tag it until that result is obtained.

Security boundaries **not established by v0.8**:

- The RSA credential is an existing software macOS Keychain identity; it has not been migrated to an independently provisioned, ACL-bound or hardware-backed signing service. A process with suitable same-user access could bypass our helper's policy.
- Node manages the HMAC secret and local audit files. Native independent recalculation rejects inconsistency, but **does not establish trustworthy provenance against a compromised Node process with that secret**. Same-user marker deletion, replacement and rollback are not mitigated.
- Touch ID checks authorize **test fixture** operations. No trusted production review UI, actual file import/export entitlement, destination selection or real file-commit result exists.
- `NO_MARKER` does not prove nonexecution; `MATCHING_MARKER` does not prove actual import success. Uncertain outcomes must never automatically retry.
- GitHub Actions automatic runs are intentionally disabled for feature branch pushes to conserve account minutes. They still run on `main` and pull requests. Prefer local `npm test` and Mac native acceptance.

**Finish criterion:** all local Node tests green and the latest integrated Mac suite passes, with the above limitations remaining explicit. Treat restricted signing-key access, independently trusted audit provenance and real transfers as separate follow-on engineering work. Do not merge, tag or change `main` without explicit authorization.
