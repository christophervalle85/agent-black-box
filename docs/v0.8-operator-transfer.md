# v0.8 Phase 5–6 — Operator-selected native transfer (Mac acceptance pending)

**Status:** Code for bounded real-byte import/export has been added on the feature branch. It remains an **opt-in Apple Development-signed, operator-only experiment**, not a production MCP file-transfer implementation. Mac runtime acceptance is pending. The existing MCP gateway and macOS required sandbox mode remain unchanged and fail closed.

## Implemented

- A native macOS Open Panel selects the import source. Node, MCP and the worker do not specify a host path. The native host opens the selected file with no-follow access, validates ownership, single regular-file link, descriptor identity, 1–2000-byte size, UTF-8 and exact SHA-256.
- A fresh native biometric-only Touch ID decision approves the immutable snapshot.
- A separately sandboxed XPC notes worker requires the real signed host's OS-verified Team ID and code-signing identifier before accepting messages. It owns its Documents scratch directory and accepts only safe test note names.
- Import performs exclusive creation of a fresh bbx-test-UUID.txt in that sandbox root and verifies exact readback. Missing acknowledgments are UNKNOWN and nonretryable.
- Export reads an explicitly named worker test note and uses native Save Panel plus fresh Touch ID. It creates only a **new** destination with O_EXCL/O_NOFOLLOW, then fsyncs file and directory. It cannot overwrite an existing file.
- The Node test harness verifies Apple Development signatures, Team ID equality, and worker App Sandbox/no-network entitlements before launching the native host. It stores redacted event metadata in a separate local HMAC audit.
- No actual host file paths or contents appear in the native success marker or audit.

## Operator-only Mac acceptance

Pull the feature branch and run npm test locally. First check only native compilation, Apple Development signing, XPC signature identities and sandbox entitlements. **This command never opens a picker or Touch ID prompt:**

    MCP_SANDBOX=off npm run mcp:mac-operator-transfer -- build-check

On a compiler failure the wrapper reports the source filename, line, column and compiler error rather than just a generic build-denied message. Then, using **only disposable non-sensitive UTF-8 text** under 2000 bytes:

    MCP_SANDBOX=off npm run mcp:mac-operator-transfer -- import

Select one such file in the native Open Panel, approve Touch ID, and copy the **actual** bbx-test-UUID.txt note identifier from a successful PASS response. If import has not succeeded, **do not run export** and do not type the literal placeholders YOUR-UUID or UUID. To export exactly that worker test note:

    MCP_SANDBOX=off npm run mcp:mac-operator-transfer -- export bbx-test-UUID.txt

Choose a new filename in the Save Panel, approve separate Touch ID consent and independently compare the exported bytes to the original selected fixture. Also test operator Cancel, an oversized file, symlinked source, pre-existing destination and attempted mismatched name. **Never use confidential files before this new path has undergone on-device acceptance.**

This does not provision a new RSA credential and does not trigger GitHub Actions. Temporary host bundles are cleaned up. Sandboxed test note data may persist across runs.

## What remains

- The earlier Keychain RSA signer deliberately authenticates the **fixed synthetic 39-byte payload only**. It is not used as an arbitrary-file signer in this operator flow. The new Touch ID UI does not establish an independently trusted production controller or Keychain ACL isolation.
- Node controls the HMAC audit key and files; independently trustworthy audit provenance against a compromised Node same-user process is not established.
- Current worker write implementation is a narrowly scoped test-note API. Crash atomicity, crash recovery for external files, directory/symlink races, durable receipt trust and restart safety remain to be validated for this new feature. Unknown operations must never be automatically retried; a partial exclusive export requires manual reconciliation.
- **Neither legacy nor modern MCP sessions expose this real-file command.** No app distribution signing, notarization or macOS required-mode release readiness is claimed.
- Before calling v0.8 fully complete, verify the new Mac compile and positive/negative operations, retain worker OS file/network denial, then finish the actual legacy/modern MCP required-mode integration and its acceptance. The 237/237 existing Node tests and earlier Keychain/XPC acceptance apply to the prior synthetic path, not the new one.

**GitHub Actions remain disabled for ordinary feature pushes; main stays unchanged until an explicit merge request.**
