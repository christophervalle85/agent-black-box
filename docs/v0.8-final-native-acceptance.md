# Agent Black Box v0.8 — Final native acceptance (NOT YET ACCEPTED)

This release-candidate branch implements a **developer-signed, macOS-only required-mode MCP backend**. The ordinary Node MCP policy/approval/audit controller remains unsandboxed and trusted; only the fixed note operations execute inside a separately signed App Sandbox XPC worker. The worker cannot use generic shell, arbitrary paths, external file transfers or network. The full required-mode feature **has not yet passed real-Mac runtime acceptance**.

A separate operator-only native picker and Touch ID import/export prototype already passed a 41-byte round trip on a real Mac with matching SHA-256. That capability is **not** exposed to MCP agents or merged into the required-mode worker.

Test failure, signal, malformed marker, unexpected consent, file alteration or ambiguous outcome **must not pass**. No personal documents are used. No retry is inferred from an uncertain write.

## Explicit native required-mode installation

Run:

    MCP_SANDBOX=off npm run mcp:mac-native-required -- install

This creates a new, private installation folder under the local operator's `~/Library/Application Support/AgentBlackBox/RequiredNativeMcp`, compiles and **Apple Development-signs** a distinct app and nested XPC worker, and creates a `0600` local Team ID pin only on first successful installation. Both the native host and worker install OS-enforced **incoming/outgoing** signed peer requirements before message processing. The worker's required-mode build omits its test-only cleanup operation. Neither this command nor required mode touches, reprovisions or rotates the previously enrolled RSA Keychain controller identity.

The installer does not silently overwrite an existing bundle or change a Team ID pin. After intentionally upgrading a signed build under the same enrolled Team ID, use **`install-replace` explicitly**. Do not use either installer option on an unreviewed branch.

Verify:

    npm run mcp:mac-native-required -- verify

The verifier checks the local private trust record, exact signing identifiers and pinned Apple Team ID, deep signed app/worker seals, and the sandbox worker's entitlements (App Sandbox required, no network entitlement). It then requests its canonical Documents scratch root through a signed native XPC handshake and prints `MCP_WORKSPACE_ROOT="..."`. Do not guess that path or substitute `demo-workspace`.

## Real MCP required-mode acceptance

After installation and verification, execute **both** commands on the Mac:

    MCP_SANDBOX=required npm run mcp:mac-xpc-mcp-acceptance -- --required-installed

    MCP_SANDBOX=required npm run mcp:mac-xpc-mcp-acceptance -- --required-installed --modern

The harness obtains the installed worker root independently, creates a fresh temporary HMAC audit and local approval controller and launches the **actual** gateway in required mode *without* experimentalLaunch injection. Legacy and modern tests require exact tool discovery, traversal denial, real approval deny/allow, XPC read/write, exclusive create rejection, HMAC audit integrity and no note-content leakage. It does **not** silently fall back to unsandboxed Node notes. Required worker creates one disposable note per test; deletion is intentionally disabled in this build, so acceptance fixtures remain in the worker's sandbox scratch root until explicitly reconciled.

After positive acceptance, ordinary standalone gateway mode must specify the exact verified `MCP_WORKSPACE_ROOT` in both the MCP gateway and local approval server environments. Missing, mismatched or untrustworthy workspace; missing/replaced trust pin; invalid Team/code signature; no XPC sandbox; unavailable OS peer verification; malformed native handshake: **fail closed**.

## Limits

This is a locally installed Apple Development prototype, not Developer ID/notarized public distribution. The parent Node/controller is not sandboxed, its HMAC audit key remains same-user accessible, and an attacker with the same user's signing credential or filesystem control may compromise the local trust anchor. The required-mode native worker supports only bounded `bbx-test-*.txt` notes and does **not** provide real host import/export or unrestricted MCP interoperability. The reviewed 39-byte Keychain RSA consent experiment and operator file-picker prototype remain separate security demonstrations. Final versioning, merge/tag, README claims and production distribution need explicit authorization and actual Mac acceptance evidence.

**No merge, PR, release tag, Keychain key rotation, or automatic feature-branch GitHub Actions changes are part of this work.**
